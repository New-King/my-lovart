# M25 · 按交接文档收紧：实拍锚定 + 实际末帧衔接

## 背景

`docs/notes/video-continuity.md` 指出的两个根因：

1. 产品 canon 允许纯文生图，第一步就是模型发明的杯子，后面怎么参考都在漂；
2. 连续性用另一张生成的 `end_frame` 近似，而不是视频实际的最后一帧，误差逐镜累积。

Lovart 本身靠角色/道具素材库 + 多角度定妆卡 + 帧级衔接，不是靠“多塞几张参考图”。本项目的流程方向对，但这两处必须收紧。

## 已实现

### P0

- **产品锚图必须基于实拍**：`role=canon, anchorType=product` 且没有 `inputImages` → `canon_photo_required`，不再产出纯文生图锚图。
- **锚图确认门禁**：锚图本轮刚生成时，关键帧返回 `canon_unconfirmed`；必须先给用户看、下一轮确认。
- **身份锁定 prompt**：keyframe/end_frame 自动追加“保持参考图主体形状/比例/接口/材质/颜色/标志位置一致，只允许改机位/光线/背景/构图”。
- **参考图收敛**：关键帧默认只带产品锚 + 主视觉锚 + 衔接帧，最多 3 张；scene/character 不再默认塞入产品镜头。
- **单一产品锚**：`setAnchorAsset(product)` 覆盖原指针，不并存。

### P1

- migration `0012`：`storyboard_shots.video_last_frame_asset_id`（已执行）。
- 视频成功后 worker 用 ffmpeg 抽最后一帧：`-sseof -0.5 -i <video> -frames:v 1 -q:v 2`；失败降级到 `end_frame`，不失败整个 job。
- 抽帧写入 `project_assets`（`origin=derived`, `metadata.role=video_last_frame`），并回写镜头。
- 下一镜生成条件改为：
  - 上一镜没有视频 → `previous_video_required`
  - 有视频优先用实际末帧；抽帧失败才回退 `end_frame`
  - 下一镜首帧的 `sourceAssetIds` 必须包含衔接帧，否则 `continuity_not_anchored`
- `end_frame` 语义收敛：只作为本镜视频的 `last_frame` 约束，不再作为下一镜来源。

### 流程

多镜头改为按镜序闭环，不再先出所有关键帧：

`锚图确认 → 镜1首尾帧 → 确认 → 镜1出片 → 抽末帧 → 镜2首帧(承接末帧) → ...`

## 验收

- `verify:video-guard` 20/20：新增 `canon_photo_required`、`canon_unconfirmed`、`previous_video_required`，并把连续性校验改为实际末帧。
- `verify:video-frame`：生成 1 秒测试视频，HTTP 与 `/files` 本地两种来源都抽出有效 JPEG（675 bytes）。
- server/web typecheck 0。

## 依赖与降级

生产环境需要 `ffmpeg` 在 PATH 中（或设置 `FFMPEG_PATH`）。找不到时抽帧返回 null，下一镜回退到 `end_frame` 并记录日志；视频作业本身不失败。
