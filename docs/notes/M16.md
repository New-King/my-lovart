# M16 · Phase 1d：PostgresSaver、thread_id 与上下文预算

## 做了什么

- 新增依赖：`pg`、`@langchain/langgraph-checkpoint-postgres`（运行时可选，未安装则自动退化为无执行记忆）
- migration `0004_thread_ids.sql`：`sessions.thread_id` + 唯一索引（已执行）
- `features/agent/persistence/checkpointer.ts`：
  - Supabase 直连地址自动转 pooler（`aws-1-ap-northeast-1.pooler.supabase.com`），避免 IPv6 直连不可达
  - `PostgresSaver` + schema `langgraph`，启动预热，`/health` 返回 `checkpointer.status/host`
  - 失败只 warning，不阻塞消息/画布持久化
- 每个 project 固定一个 thread：`sessions.thread_id` 懒创建、写回数据库；DB 不可用时退化为进程内 thread
- runtime：有 checkpointer 时只发当前 `HumanMessage`，历史/工具结果由 checkpoint 恢复；第一次启用时若 thread 为空，会把已有产品历史种进去，避免旧项目突然失忆
- 退出手工 history 与 checkpoint 并存的重复；无 checkpointer 时仍走原 history
- deepagents 默认 `SummarizationMiddleware` 负责长 thread 压缩；trace 记录 `checkpointEnabled / checkpointHasState / messageCount`
- 无 checkpointer 时的 history 加预算：最多 20 条、单条 4000 字、总 12000 字
- 视觉预算：
  - 前端上传前把长边 >1600 的图缩到 1600，必要时转 JPEG，避免 10MB 原图直接进上下文
  - 服务端兜底：单张 data URL > 3.5M 字符或总量 > 9M 字符不塞给 provider，并写 `vision.budget` trace
- `/health` 增加 `checkpointer` 状态
- 删除项目时同时清理对应 thread 的 `checkpoints / blobs / writes`，不留下孤儿数据

## 验证

真实 Supabase + 真实模型 + 真实 HTTP：

1. 新项目第一轮：“记住：我的项目代号是 ORBIT-9” → 回答“收到。”
2. 同一进程第二轮：“我的项目代号是什么？” → `checkpointHasState=true`、`messageCount=1`、回答 `ORBIT-9`
3. **杀掉服务、重新启动**，同一项目第三轮：“重启后继续：我的项目代号是什么？” → 同一 `thread_id`、`checkpointHasState=true`、回答 `ORBIT-9`

数据检查：

- `langgraph.checkpoints / checkpoint_blobs / checkpoint_writes` 有该 thread 的记录
- 测试 project、checkpoint thread 已清理，没留下测试数据

`/health` 返回：

```json
{"checkpointer":{"status":"ready","host":"aws-1-ap-northeast-1.pooler.supabase.com"}}
```

## 运行要求

新增了两个依赖，需要在本机执行一次：

```bash
pnpm install
```

不装也能启动：`/health` 会显示 `checkpointer.status=disabled/error`，消息/画布/产物账本不受影响，只是没有跨轮工具记忆。
