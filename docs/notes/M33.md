# M33 · 素材库入库（修刷新丢失）

日期：2026-11-17
关联：`docs/specs/materials-library.md`、`supabase/migrations/0014_user_materials.sql`

## 问题

用户上传素材后刷新页面，素材消失。原因不是“没保存成功”，而是前端 `materials-api.ts` 一开始就是假接口：注释写着“素材只存在内存里，刷新页面后消失，接后端时替换这里”。上传没有发请求，自然没有入库。

## 做了什么

- 新增 `user_materials` 表（按用户，不按项目），migration 0014 已在 Supabase 执行；
- 服务端 `features/materials`：仓库（supabase/memory 双实现）+ 服务（data URL → `/files/:id` + Storage，写记录）；
- `GET /materials`、`POST /materials`、`POST /materials/:id/delete`，全部需要登录；
- 删除时清 DB、Storage 和进程内副本；`file.store` 增加删除墓碑，避免 Storage 最终一致期间把删除的文件重新缓存回来；
- 前端 `materials-api.ts` 改为调用真实接口，沿用聊天附件的缩图预处理；
- 面板加载失败显示错误 + 重试；上传/删除失败保留列表并提示；
- 旧的内存素材无法恢复，用户需重新上传一次。

## 验收

`verify:materials` 11/11（真实 Supabase + Storage + 魔法链接 JWT）：

- 上传 201、URL 为 `/files/:id`、尺寸入库；
- 重新 GET 仍能读到（刷新等价）；
- Storage 对象真实存在；
- `/files/:id` 可读；
- 非图片 400；
- 删除后列表消失、文件 404、Storage list 里不存在。

期间发现：用同一个 service_role client 调 `auth.verifyOtp` 换 JWT 会把客户端切成用户会话，后续 Storage 写入吃 RLS 403。验收脚本改为用独立 anon client 换 token，`getDb()` 始终保持 service_role。

## 已知边界

- 单文件 12MB 上限；客户端先缩图；
- Storage 删除最终一致，短时间 CDN 可能还能下载旧对象，但服务端不会再缓存；
- 公共素材仍是本地 mock 只读。
