# M12 · Phase 1a：消息与画布持久化

## 做了什么

- 新增 `workspace.repository.ts`：Supabase 实现 + schema 探测 + 内存回落
- 消息读写：`appendUserMessage` 立即写库；助手消息开始写一条 queued，结束/取消/失败时更新整条消息（content / blocks / parts / steps / thoughts / options / status / failure）
- 画布读写：`load` 时读 `canvases.elements` 和 `canvases.files`；保存时写回
- 每个项目固定一个 session、一个 canvas（唯一索引 + 并发冲突重读）
- `workspace.service` 的 get / saveCanvas / appendUserMessage 改成异步；首次访问时 hydrate 内存缓存
- workspace 路由校验项目归属，避免登录用户访问别人的项目
- migration `0002_workspace_persistence.sql`

## 验证

用 fake repository 跑通：

- 用户消息立即写入
- mock 运行结束后助手消息为 completed，content 47 字、blocks/parts 各 4 段
- 新 service 实例 `get()` 能 hydrate 回完整消息

真实 Supabase 还没跑：sandbox 无法解析 `db.<ref>.supabase.co`，而且 DDL 不能通过 REST 执行。迁移需要用户在 Supabase SQL Editor 执行，或在本机按连接串跑。

## 当前行为

- 迁移未执行：服务启动后探测缺列，打印警告并回落到内存，功能不受影响
- 迁移执行后：消息、画布、Excalidraw files 全落 Supabase（files 暂时存 jsonb，Phase 1b 迁 Storage）
- 服务重启后同一 project 的消息和画布会恢复；附件/生成文件仍在内存 `/files`，重启后旧图 404，Phase 1b 解决

## 下一步

Phase 1b：Excalidraw files 落 Storage、附件 asset_id 稳定化、PostgresSaver checkpointer、视觉附件压缩预算。完成后跑 G13 刷新恢复。
