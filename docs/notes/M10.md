# M10 · 视觉输入与生成前校验

## 做完的事

- 参考图现在不仅写进 `<input_images>` XML，还作为 OpenAI 兼容的 `image_url` 内容块随 `HumanMessage` 发给模型。之前模型只看得到文件名，所以问「这是谁」时只能按文件名猜
- 最多携带 4 张图：本轮附件优先，然后是最近几轮发过的图；和 `<input_images>` 的 asset_id 顺序一致
- 消息里补了一句 `vision_note`：参考图已经随消息提供，可以直接看画面，不要只凭文件名判断
- 提示词增加生成前自检：上一轮问过但用户没回答的关键项，不要用默认值悄悄补齐后直接生成；视频尤其要先确认平台/画幅和风格基调

## 为什么

- 用户发截图问「这是谁」，模型回答「只拿到文件名，按文件名判断」，说明视觉内容根本没进模型上下文
- 用户只回答了时长和品牌，Agent 却自行默认 3:4、暗调暖光后直接生成视频。视频耗时且不可逆，应该在关键项没齐时先问完

## 验证

- 用一张白底黑字 `HELLO 2026` 的测试图问「这张图里写了什么」，模型正确读出文字，证明视觉链路通了
- 按截图 1 的上下文模拟：上一轮问了平台、内容、风格，用户只答「5 秒 + 品牌 newking」 → 模型没有调用 `generate_video`，而是继续确认画面比例和内容/调性

## 已知问题

- 最多带 4 张图，没有做服务端压缩/尺寸预算；特别大的截图会占用较多上下文
- 历史里只有最近附件能作为视觉内容，更早的截图仍然只有文字记录
- 没有接 checkpointer；对话记忆仍是消息文本重放 + 最近附件重注入
- 没有接 LangSmith。它解决的是 prompt/工具调用的可观测与评测，不解决记忆；当前调试主要靠 SSE 事件和服务端日志
