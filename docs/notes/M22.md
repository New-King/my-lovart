# M22 · 视频前期闸门：脚本 + 首帧确认后才出片

## 问题

用户给了一个 5 秒自行车广告需求，回答三张追问卡后，助手**当轮直接调用 `generate_video`**，没有脚本、没有场景/资源图、没有确认。

## Trace 证据

trace `2026-11-15T07-27-58-811Z-e9e76e36`：

- `model.request` 的 userText 只有三个答案，`projectAssetCount: 0`；
- 请求里没有 `storyboardCount` / `activeStoryboardId` 等 Phase 2.5 字段；
- `tool.start` 紧接着就是 `generate_video`，没有 `create_storyboard`，没有 `generate_image`；
- `checkpointEnabled: false`。

说明当时请求跑在**重启前的旧 server 进程**上（Phase 2.5 的上下文与分镜工具未加载），`pnpm dev` 没有真正重启。这一点是触发问题的直接原因。

但只靠重启不够：旧/新 prompt 与工具都没有硬约束“视频必须先有已确认的脚本和首帧”，模型仍可能越过前期直接出片。Lavart 仓库本身也是把“视频/动态”直接映射到 `generate_video`，只在前端面板提供首尾帧上传，没有强制脚本确认。所以这里按用户要求做得比 Lavart 更严格。

## 修复

### 1. 服务端硬闸门

`features/agent/tools.ts` 新增 `checkVideoPreflight(context, shotId, direct)`，在 `generate_video` 处理函数最前面调用；不通过就返回结构化错误，**不会解析参考图、不会提交作业、不会调用 provider**：

| code | 条件 | 指示 |
| --- | --- | --- |
| `video_plan_required` | 没有 `shotId` | 先建脚本/镜头，出首帧，等确认 |
| `video_plan_unconfirmed` | 镜头是本轮新建的（`createdAt >= runStartedAt - 2s`） | 先把脚本/镜头列表给用户并停止 |
| `keyframe_required` | 镜头没有 active 图片资产 | 先 `generate_image(shotId)` |
| `keyframe_unconfirmed` | 首帧是本轮刚出的 | 先展示关键图，等确认 |

只有用户明确说“直接出片/不用确认”时，模型才可传 `direct: true` 跳过。2 秒容差用于容忍 DB 时钟与 app 时钟的小偏差。

### 2. 提示词

`agent/prompt.ts` 新增「视频流程（硬性要求）」：平台/画幅/时长 → 可执行脚本（5 秒也要 2–3 个节拍）→ `create_storyboard`（单条视频也建 1 个镜头）→ `generate_image(shotId)` 首帧 → 给出脚本/镜头表/关键图并停下 → 下一轮确认后才 `generate_video({shotId, inputImages:[关键图]})`。

同时把“信息足够就直接推进”“视频 → generate_video”改成图片可直接推进、视频必须走前期；禁止“确认后我直接出片”却本轮已提交。

### 3. 验收

`apps/server/scripts/verify-video-guard.mjs`，不调用视频服务：

- 无 `shotId` → `video_plan_required`
- 本轮新建镜头 → `video_plan_unconfirmed`
- 上一轮镜头但无首帧 → `keyframe_required`
- 已有上一轮脚本 + 首帧 → 放行
- 首帧本轮刚出 → `keyframe_unconfirmed`
- `direct=true` 显式跳过 → 放行

结果 6/6 通过；临时项目已删除，无残留。server typecheck 0。

## 注意

改完必须真正重启 `pnpm dev`（旧进程不会热更新 server 的新工具/提示词）。即使模型仍尝试直接出片，服务端闸门也会把它挡回“先给脚本和首帧”。最终视频生成按约定不在本轮测试。
