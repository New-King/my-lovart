# M38 · 过程区显示模型思维链

日期：2026-11-17
关联：`apps/server/src/features/agent/runtime.ts`、`apps/web/src/components/run-process.tsx`、`packages/shared/src/index.ts`（已有 `thinking.*` 事件）

## 为什么做

用户看到的过程区只有工具调用，没有模型的思考。对比其他 Agent IDE：一轮里调用 10 个工具时，每个工具上方会有一行截断的思考，点开看完整内容。用户要求同样的“完整思维链”。

契约里其实早就有 `thoughts`、`thinking.started/delta/completed`，前端 `RunProcess` 也会渲染 `ThoughtRow`；问题在真实 runtime 从来不发这些事件，只有 mock-agent 会发。`readChunkText` 还显式过滤了 `thinking/reasoning` 块。

## 服务端

`runAgent` 的 `on_chat_model_stream` 现在读取两类推理内容：

- DeepSeek / OpenAI 兼容：`chunk.additional_kwargs.reasoning_content`
- Anthropic / 其他：`content` 里 `type: "thinking" | "reasoning"` 的块

按“一次模型回合 = 一段思考”切分：

- 第一段 reasoning 到达 → `thinking.started`；
- 后续增量 → `thinking.delta`；
- 同一回合出现正文或 `tool_calls/tool_call_chunks` → `thinking.completed`；
- `on_chat_model_end`、`on_tool_start`、取消、异常、运行结束都会兜底收尾，避免永远停在“思考中”。

思考不会进入 `answerText`，也不会进 `message.delta`；最终回答仍是模型正文。单段最多保留 60,000 字符，超出追加“已截断”标记。trace 只记录事件类型/字符数，不落原始思维链。

## 前端

`ThoughtRow` 从“思考过程”占位改成：

- 折叠：一行截断的思考摘要（`title` 不塞全文），右侧耗时 + 展开箭头；
- 展开：完整 `whitespace-pre-wrap` 文本；
- 流式时摘要带 shimmer；
- 与工具行按 `startedAt` 排序，形成“思考 → 工具 → 思考 → 工具”的顺序。

持久化复用已有 `thoughts` 字段（migration 0002），刷新后仍在。

## 模型行为差异（重要）

当前 `.env.local` 是 `LOOMIC_AGENT_MODEL=deepseek-v4-flash`，接 DeepSeek 兼容端点。实测：

- `deepseek-v4-flash`：同一探针经常返回空 `reasoning_content`（28 个工具时尤其明显），偶尔只有 2 个字符；不是代码丢事件，是供应商/模型选择。
- `deepseek-v4-pro`：同一探针稳定返回完整 reasoning，9/9，思考在 `tool.started` 之前，且持久化到消息 `thoughts`。
- 供应商 `/models` 只列出 `deepseek-flash`、`deepseek-v4-pro`；`deepseek-v4-flash` 是可用别名。

用户明确选择：**不改模型配置，模型没有思考就不显示**。因此：

- 功能对任意模型都生效；
- 不返回 reasoning 时过程区不会出现空思考行，也不报错；
- 想看稳定思维链时，把 `LOOMIC_AGENT_MODEL` 换成 `deepseek-v4-pro` 再重启即可。

## 验收

- `pnpm --filter @my-lovart/server verify:reasoning` 6/6（不调模型）：
  - `additional_kwargs.reasoning_content`；
  - content 的 `thinking` / `reasoning` 块；
  - 空串/null 不产生思考；
  - 普通正文不误判；
  - `tool_calls` / `tool_call_chunks` 能结束当前思考段。
- `run:reasoning-probe`（真实模型，两轮：inspect_canvas + 17+25）：
  - `deepseek-v4-pro` 9/9：1 段思考 91 字，`thinking.completed` 在 `tool.started` 之前，消息 `thoughts` 有内容；
  - `deepseek-v4-flash`：输出 `SKIP` 并 0 失败——供应商未返回 reasoning 属预期，不算链路失败。
- `apps/server` / `apps/web` typecheck 通过。

## 取舍

- 展示的是模型原始 CoT，语言可能和用户中文不一致（常见英文），这是模型行为，不做翻译/改写。
- 60,000 字符上限是为了防止异常模型撑爆 SSE/DB；正常设计任务远低于此。
- 目前只在一次 run 内流式发送，思考的中间状态不逐 chunk 持久化；终态消息会保存完整 `thoughts`，刷新后可见。
- 如果以后换到不暴露 reasoning 的闭源模型，可以考虑用模型可见的“计划句”生成轻量步骤摘要，但那不是完整思维链，需单独立场景。
