# M29 · 一致性策略不再全局写死

日期：2026-11-16
关联：`apps/server/src/features/storyboards/policy.ts`、`apps/server/src/features/agent/tools.ts`、`apps/server/src/features/agent/prompt.ts`

## 问题

上一版把所有视频都按“产品广告”处理：没有产品实拍就 `canon_photo_required`，开盖没有细节实拍就 `product_state_reference_required`，提示词也强制“必须先要实拍”。用户指出客户可能提供参考图，也可能不提供；视频类型也不同，不能写死一套流程。

## 实现

新增每个分镜自己的 `metadata.consistency`：

| 策略 | 产品锚 | 细节锚 | 关键帧/出片 |
| --- | --- | --- | --- |
| `strict` | 必须有真实实拍 | 必须有真实细节实拍 | 必须 canon + keyframe + 多镜头末帧衔接 |
| `adaptive`（默认） | 有实拍用实拍；没有可生成设定图并警告 | 可基于产品设定图生成草案 | canon + keyframe 默认仍要；多镜头按末帧衔接 |
| `loose` | 可直接文字生成 | 可跳过 | 可无 canon/首帧直接出片，不强制末帧衔接 |

- `create_storyboard` / `update_storyboard` 支持 `consistency` 参数；存 `storyboards.metadata`，不需要新 migration，旧分镜默认 adaptive。
- `planImageReferences` 按分镜策略决定是否拒绝；adaptive 生成设定图时在工具结果里返回 `warning`，明确“这是生成图，不是客户真实产品”。
- `checkVideoPreflight` 在 loose 下放宽 canon/keyframe/末帧衔接，保留 `video_plan_unconfirmed`（脚本仍要让用户看到）。
- `<project_state>` 增加 `consistency` 属性，Agent 每轮都能看到当前档位。
- 系统提示词从“硬性要求”改成“默认路径 + 按 consistency 调整”，不再一律要求用户上传实拍。
- 工具仍负责结构约束：镜头时长、总时长、canon 血缘、多镜头顺序；这些是 provider 能力边界，不是风格偏好。

## 验收

`verify:video-guard` 30/30：

- strict 下无产品实拍 → `canon_photo_required`
- strict 下无细节实拍 → `detail_photo_required`
- adaptive 无实拍 → 允许生成产品设定图，返回 warning
- adaptive 无细节实拍 → 允许生成细节锚图草案
- loose 无 canon/首帧 → 允许直接生成草稿
- loose 多镜头 → 不强制上一镜视频/末帧衔接
- 原有 strict/adaptive 闸门全部保持
- 否定句“不要出现开盖/螺纹/内胆”不再误判为状态要求

## 取舍

- loose 不是“质量模式”，只是快速草稿；交付前应切回 adaptive/strict 重跑。
- adaptive 的生成细节锚图仍可能发明结构，只是不再把流程卡死；真实还原仍需要 strict + 实拍。
- 还没有按项目/客户保存默认策略；目前由分镜 metadata 决定，Agent 在建分镜时选择。
