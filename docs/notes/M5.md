# M5 · 开场引导与信息确认

## 做了什么

- 空对话改成开场引导：给「海报 / 短片 / 封面」三个可直接改写的起手提示，保留上传参考图入口，并说明 AI 会先确认关键信息
- Agent 增加追问协议：一次只问一个最关键的问题；有 2-4 个离散选项时，在最后一行输出 `[OPTIONS]选项一|选项二|选项三[/OPTIONS]`
- 服务端在流式文本里识别并剥离这段协议，跨 chunk 缓冲半个标记，转成新的 `message.options` 事件；正文里不会漏出协议
- 选项随消息落库，前端在最后一条助手消息下渲染成快捷按钮，点一下就把选项原话发回去，不用再手打
- 纯开放性问题不配按钮；用户已经回答过的不再追问，信息够了直接生成
- 生成完成后也可以用同一协议给 2-3 个下一步动作（换比例、再来一版、改风格），点击即继续
- 补充「像设计师一样」的工作方式：先判断交付物和用途，再定构图与比例；能合理默认的偏好不问；产物完成就收尾并停止调用工具

## 为什么

参考 Video_Remix_Benlai 的需求采集守则：按钮轮正文要短（1 句承接 + 1 句问题），选项要是用户口吻的完整选择，一次只推进一个问题。这样用户不用写长 prompt，也不会被一次问五个问题劝退。协议仍然走原有 SSE 事件层，生成链路和取消逻辑不变。

## 已知问题

- 选项是单选题；需要「多选」或「补充自定义」时还没有对应交互
- 协议靠文本标记，模型偶尔可能不遵守（例如正文里解释协议）；目前只取第一组，多余内容会作为普通文本保留
- 没有自动化测试覆盖跨 chunk 的标记切分，只做过真实模型的端到端验证
