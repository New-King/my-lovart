# M5 · 对话引导与需求追问

## 做了什么

- 空对话改成开场引导：给「海报 / 短片 / 封面」三个可直接改写的起手提示，保留上传参考图入口
- 追问分两档：
  - 信息很少（缺两个以上关键项，或只有一句模糊目标）→ 不出按钮，用 Markdown 清单问 2-3 个关键问题，问完就停
  - 只差一个关键项 → 一句承接 + 一句问题；如果有 1-3 个清晰互斥的候选答案，调用 `offer_choices` 工具，把答案渲染成按钮
- 按钮只回答「正在问的这个问题」，不能是「已经传好了」「刷新看看」「先占位」这类寒暄、确认或下一步动作；素材缺失只请用户上传
- 生成完成后不再给下一步按钮，最多一句话说明可以怎么改
- 选项按钮来自工具事件而不是正文标记：服务端在 `on_tool_end` 里把 `offer_choices` 的输出转成 `message.options`，正文里不会出现协议字符
- 按钮下面提示「也可以直接输入其他答案」，用户随时可以在输入框自由回答
- 画布为空时，`<canvas_state>` 明确写「不要引用画布上的图片，也不要假设用户已经上传」

## 为什么

之前每条回复都可能带按钮，而且按钮常被模型当成「下一步建议」，看起来像联想词而不是追问。现在用工具把「候选答案」和「下一步动作」区分开：只有需求采集阶段、只差一个离散信息时才出按钮；信息太少时用结构化文字问，避免用户被一堆按钮推着走。

## 已知问题

- 选项是单选；多选、带自定义输入的组合还没有
- 模型仍可能判断错「缺几个信息」，需要靠提示词约束，没有服务端硬校验
- 工具调用不会显示在运行过程时间线里，用户只看到问题下面出现按钮
