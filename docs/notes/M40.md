# M40 · 视频动作镜头：主角错位

日期：2026-11-17
关联：`apps/server/src/features/agent/tools.ts`、`prompt.ts`、`docs/specs/video-preproduction.md`

## 用户看到的结果

10 秒公路车广告，第 1 镜 5 秒。产品设定图是棚拍整车（左图），首帧是“前景一辆大车停在路上 + 远处路上一个很小、几乎看不清的骑行者”（右图）。用户看到的主体就是前景这辆大车。生成视频后：这辆大车全程没动，远处那个小人骑着车慢慢靠近、超过前景车、消失在镜头里。

用户问：这条 5 秒到底想传达什么？文案错还是制作错？缺人物还是主角搞错了？

## 聊天记录还原

trace `2026-11-17T05-19-34` / `05-20-20` / `07-22-18`：

1. canon prompt 明确写“无人物、无文字、无品牌 logo”，生成的是 45° 棚拍产品图。
2. 第 1 镜描述：“公路竞速车从画面前方远处高速压弯逼近，车身向弯内侧倾斜。” 首帧 prompt 同样没有写骑手。
3. 生成首帧时模型被要求“远处压弯逼近”，但产品图没有骑手；它在远处补了一个骑手，前景保留了产品车，形成两个主体。
4. 视频 prompt：“公路竞速车从画面深处高速压弯向镜头逼近……镜头后拉跟随，保持车在中偏右、逐渐变大。”
5. `generate_video` 用首帧做 image-to-video，`direct:true`（当时的运行没有触发 direct 校验/预检）。图生视频只能动首帧里已有主体：它选择了远处唯一像“会骑车的人”的对象，把前景产品车当成背景。

结论：**不是文案单独出错，也不是视频模型随机发挥，而是首帧和动作设计不一致。** 这条片子想传达“产品车在盘山弯道高速压弯逼近”，实际传达的是“一辆停在路边的车，看着别人骑过去”。主角错了，动作主体缺了。

## 为什么首帧会是一辆静止的车

除了“没写骑手”，还有一个更直接的代码原因：关键帧生成时服务端会追加一段身份锁：

> 严格保持参考图主体的身份一致……只允许改变机位、光线、背景与构图。

这段锁本来是为了防止产品变形，但它同时冻结了参考图的**姿态**。参考图是无人物、直立的棚拍产品；模型于是把同一辆直立单车“贴”进盘山公路，既没有骑手，也没有压弯。它以为自己在正确执行“身份一致”，实际产出的是一张漂亮的静物广告，不是动作首帧。

所以首帧里的大车不动是必然的：图生视频拿到的是一个“停着的产品”，没有任何运动线索；它只能去动远处那个唯一像骑行者的对象。

修复：`planImageReferences` 现在返回 `actionSubject`。动作镜头的身份锁改成：

> 严格保持车型/比例/材质/配色/标志位置；但不要复制参考图的棚拍构图和静止姿态。按文字重新构图，把执行动作的骑手/人物和动作姿态画进画面，只锁身份，不锁姿势。

非动作镜头仍用原来的严格身份锁。

## 为什么是系统问题

- 产品 canon 是“无人物、静态、棚拍”，只适合锁车型/配色/材质；
- 动作镜头却直接拿它当首帧，指望图生视频补出骑手和压弯姿态；
- 视频 prompt 又用“从画面深处”描述运动，正好指向背景里的第二个骑手；
- `direct=true` 在旧代码里提前跳过 preflight，动作主体检查根本没有机会执行。

这不是“改一句 prompt”能稳定解决的，因为下一次仍会生成“前景产品 + 远处骑手”。

## 修复

### 服务端闸门

- `promptRequiresHumanAction(text)`：识别压弯/骑行/摇车/踩踏/起身/奔跑/挥手等人物动作；车辆位移要求“车型 + 驶入/冲来/冲进”同句出现。否定句（“不要骑手压弯”）不算。
- `promptMentionsActor(text)`：识别骑手/车手/人物/主角/运动员等；否定句里的“无人物/不要骑手”不算。
- `generate_image(role=keyframe)`：动作存在但没有主体 → `action_actor_required`，要求补“骑手压低身体压弯”的动作首帧，或改成纯产品运镜。
- `generate_video`：把视频 prompt 和分镜/首帧 prompt 一起检查；`direct=true` 不再提前绕过，先做动作主体检查。用户上传图 / `referenceDirect` 例外，因为图里可能本来就有主体。
- 纯产品运镜（环绕、推近、光影扫过、轮组转动）不触发，避免误伤。

### 提示词

- 动作镜头先看“谁在做动作”；无人物产品图不能直接当动作首帧。
- 视频 prompt 必须以首帧可见状态为起点：首帧主车在近景，就写“画面近景的主车开始…”，不能写“从画面深处驶来”。
- 首帧只能有一个主角；negativePrompt 明确“不要第二个骑手、第二辆车”。
- `direct=true` 只用于用户自己提供的主体图，不能拿生成的产品设定图/关键帧给动作镜头兜底。

## 这不是通用方案

`action_actor_required` 和身份锁分支是**收口措施**，不是最终方法论：它们只挡显式矛盾（写了动作但没写主体、动作帧被静物姿态锁死）。同义词、隐含动作、背景第二主体、首帧姿态是否真的对，仍然无法保证。

通用方案是把镜头变成结构化状态：`subject / action / camera / startState / endState / allowedMotion`，由服务端校验和拼 prompt，见 [`docs/specs/video-shot-model.md`](../specs/video-shot-model.md)。关键词表只作为旧分镜的兜底，不应继续往里堆项目案例。
