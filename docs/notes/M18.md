# M18 · 追问卡：逐题回答，不再像后续联想

## 问题

上一版 `offer_choices` 把一题的候选答案铺成一行圆角 chip，和 Lavart 的“继续追问 / 下一步建议”长得一样；用户无法判断这是回答还是建议，且多个问题被混在一条消息里，不能逐题作答、不能每题自定义。

参考图（用户提供）的行为：一张「提问」卡，右上角 `1 / N`，每题一组 A/B/C/D 选项，每题都有自定义输入；最多同时露出两组，答完一组自动滚到下一组；底部跳过/提交。

## 协议与后端

- `packages/shared`：
  - `ChoiceOption { id, label }`
  - `ChoiceQuestion { id, question, options, allowCustom? }`
  - `ChatMessage.questions?: ChoiceQuestion[]`
  - 新事件 `message.questions`（保留旧 `message.options` 兜底历史数据）
- `offer_choices` 入参：1–3 个 `questions`，每题 2–4 个选项；工具输出稳定的 `q1/q1o1` id，`allowCustom` 默认 true。
- runtime 在 `on_tool_end` 解析 `questions` 并推 `message.questions`；工具正文只留一句承接。
- 持久化：migration `0006_message_questions.sql` 给 `messages` 加 `questions jsonb default '[]'`；repository 读写该列，刷新/重启不丢。
- prompt：只有 1–3 个关键项且每项都有清晰互斥候选时才用 `offer_choices`；正文不得重复问题/选项，也不要用「以上/下面」指代题目（卡片在回复下方）。开放性问题仍走 Markdown 清单。

## 前端

`ClarificationCard`：

- 头部「提问」+ `‹ 1 / N ›` 翻页；翻页和滚动联动（按组对齐）。
- 每组：问题、A/B/C/D 选项（选中反色）、E 自定义输入；选中即记录，输入自定义会顶掉选项。
- 容器 `max-h-[430px]`，按当前字号/间距正好露出两组，其余在卡内滚动。
- 选中一组后 180ms 自动滚到下一道未答题；最后一题不滚。
- 底部「跳过 / 提交」：跳过逐题前进，最后一题无答案发“先跳过，按你的判断先来一版”；提交把所有已答项拼成 `我的回答：\n1. 问题：答案…`。
- 发送失败（`handleSend` 返回 false）会恢复卡片可编辑，不会卡死在已提交态。
- 只对最后一条、非 streaming/queued 的助手消息渲染；旧 `message.options` 仍走 chip 兜底。

## 验证

真实模型（DeepSeek + Seedream，临时项目，测完删除）：

- 输入「帮我设计一张咖啡海报」→ 正文一句承接 + `message.questions` 三题，每题 4 个选项；`messages.questions` 与 SSE 一致。
- 用卡片同款格式发「我的回答：1… 2… 3…」→ 模型不再追问，直接出图：Seedream 30.6s，`project_assets` 有「暗调影棚咖啡海报」，画布元素 `customData.assetId` 与资产 id 一致。
- server/web typecheck 均 0。
