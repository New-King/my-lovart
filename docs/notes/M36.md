# M36 · 多镜头改为批量前期：锚图确认后一次做完所有分镜图

日期：2026-11-17
关联：`docs/specs/video-preproduction.md`、G46、`run:batch-preproduction-probe`

## 问题

用户确认产品设定图后，Agent 只生成第 1 镜首帧，停下来问“这一帧可以的话我就出第 1 镜成片”；接下来还要再确认视频、再生成第 2 镜首帧……用户要对话很多次。

根因不是模型啰嗦，而是提示词把多镜头写成“一次只做一个镜头的闭环”，服务端 `planImageReferences` 还要求“上一镜必须先有视频”才能生成下一镜首帧。于是批量前期根本做不到。

## 修正

1. 提示词改成批量前期：
   - 用户确认锚图后，下一轮**一次性生成所有镜头的 keyframe + end_frame**，统一汇报，附完整脚本方案；
   - 默认停点只剩两个：锚图确认、“全部分镜图 + 脚本方案”确认；其他不逐镜停；
   - 用户确认方案后按镜序连续出片，不再每镜问一次。
2. 服务端解禁“上一镜没视频就不能生成下一镜关键帧”：批量时下一镜首帧用上一镜**尾帧**做预览衔接；真正出片时才按镜序，并改用上一镜**实际末帧**作起始帧。
3. `generate_video` 取帧优先级改为：上一镜实际末帧 > 本镜预生成首帧 > 用户 canon。这样即使所有分镜图提前生成，成片仍从上一镜真实末帧接上。
4. 取消 `continuity_not_anchored` 闸门：续镜的连续性由出片时的实际末帧保证，不再要求预生成首帧的血缘。
5. 画幅锁定：视频分镜必须传 `aspectRatio`；`generate_image` 的 canon/keyframe/end_frame 优先跟随分镜画幅，修掉“16:9 片子出 9:16 关键帧 / 3:4 canon”的问题。

## 验收

`run:batch-preproduction-probe` 7/7（真实模型 + 假方舟出图，不烧额度）：

1. 第一轮出 3 个问题；
2. 答完建分镜 + 产品 canon；
3. 用户确认 canon 后，同轮批量生成两镜首尾帧（不是只做第 1 镜），没有调用视频；
4. 结尾给完整脚本方案并问“要按这个顺序出片吗？”；
5. 用户确认后直接调用 `generate_video`，没有重新生成分镜图。

## 还没做

- 真实两镜视频连续出片（含实际末帧接第 2 镜）没跑；视频额度紧。
- 批量生成 4 张图可能需要数分钟；进度卡片能显示，但 UI 尚未针对“连续多张图”做聚合展示。
- `strict` 批量前期仍要求真实产品实拍；没有实拍会停在补素材，不会批量乱出。
