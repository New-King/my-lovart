# M13 · Phase 1b：Storage 与稳定 asset_id

## 做了什么

- Excalidraw 的 `files` 不再整块 base64 存数据库：上传到 Supabase Storage bucket `project-files/{projectId}/{fileId}`，`canvases.files` 只保存 manifest（id/mime/path/时间）
- 加载画布时按 manifest 下载回 dataURL；老的 dataURL 条目原样兼容
- 同一 fileId 已有 path 时直接复用，避免每次自动保存都重复上传
- 聊天附件与生成结果也写入同一个 bucket 的 `attachments/{id}`；`/files/:id` 在内存没有时会从 Storage 下载，重启后旧图不再 404
- 附件 asset_id 从每轮 `asset-1…` 改成稳定的 `asset-${attachment.id}`，给后续 checkpointer 做准备
- `normalizeAttachment` / `normalizeAttachments` / `getFile` / `fileDataUrlFromUrl` / `buildAttachmentContext` 改为异步

## 验证

真实 Supabase：

- 画布 files：保存后 manifest 只有 `id/path/mimeType/created/lastRetrieved`，新 service 实例加载能拼回 `data:image/png` dataURL
- 附件：进程 A 上传后，进程 B 用 `getFile(id)` 能从 Storage 下载（70 bytes，image/png），`fileDataUrlFromUrl` 能转回 data URL
- 测试 project 与 Storage 对象都已清理

可复现验收：

```bash
pnpm --filter @my-lovart/server verify:persistence
```

脚本会创建临时 project，检查消息、画布、manifest、Storage 回读，然后 cascade 删除；全部 PASS 才算通过。
