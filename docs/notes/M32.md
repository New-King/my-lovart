# M32 · 灵感搜索接入（Pexels）

日期：2026-11-16
关联：`apps/server/src/features/inspiration/pexels.ts`、`apps/server/src/features/agent/tools.ts`、`apps/web/src/components/chat-blocks.tsx`、`docs/specs/inspiration-search.md`

## 参考项目结论

`Video_Remix_Benlai` 确实有真实图片灵感搜索：

- `api/desktop_gateway.py`：`_search_pexels_photos` 调 `https://api.pexels.com/v1/search`；
- `_build_wireless_canvas_reference_search_plan` 让 LLM 生成检索方案（title/section_label/query/color/orientation/per_page），一次最多 6 张；
- 结果以 inspiration bundle 渲染成卡片；
- 它自己的守则明确：`search_references` 是通用原子动作，不是视频固定前置；用户已有素材时跳过；搜完应停在结果让用户选，或由 action_plan 决定下一步。

## 我们做了什么

新增 `search_inspiration` Agent 工具 + Pexels adapter：

- 1-3 个方向，每个方向 4-6 张；
- 返回多个 `InspirationBlock`，复用已有的灵感卡片 UI；
- 卡片下提示“点左上角箭头加入对话，选一张作为方向”；
- 用户选中后成为下一轮消息附件，再作为 `inputImages` 进入产品设定图/关键帧；
- 搜完本轮只选方向，不自动生成设定图/分镜/视频；
- 有产品实拍/参考图/logo 或只是改图时跳过。

真实 Agent 行为回放（假 Pexels）还发现：模型会说“三组方向已生成到画布”。灵感卡片实际在对话里，不在画布；已加提示词“灵感卡片在对话里，不是画布产物”，并要求让用户点卡片加入对话/回复第几组第几张。

## 第二轮补强：文字选图必须真的能定位

第一次真实回放暴露了两个问题：

1. 卡片没有编号，用户说“第 2 组第 2 张”时两边对不上；
2. 第二轮模型直接重新搜了一遍图，并且生成时带的参考图不是用户指的那张——因为工具输出不在本轮上下文里。

修复（不是加提示词打补丁）：

- `search_inspiration` 返回值加 `selection`：`G2-2`、组/张序号、title、imageUrl；
- 消息 `blocks` 里本来就有灵感块，服务端每轮从最近一条含灵感块的消息重建 `<last_inspiration>`（组/张 + imageUrl），只在用户这句话像“第几组/第几张”时注入；
- 前端卡片显示“第 N 组”和 `2.3` 角标，提示语带组号；
- 提示词明确：有 `<last_inspiration>` 就按编号取 imageUrl，不要重新搜图；
- 没配 `PEXELS_API_KEY` 时 `search_inspiration` 仍注册：调用会在过程里失败标红并说明缺 key，提示词禁止连续重试，改用文字给方向。（2026-11-17 从“不注册”改回，避免用户看不到为什么没搜图。）

这比依赖 checkpointer 保留工具输出更稳：灵感块是消息的一部分，DB/内存都能读。

## 关键问题：真实 key 不在仓库里

`Video_Remix_Benlai` 只有 `config/config.example.yml`：

```yaml
resource:
  pexels:
    api_key: API_KEY
```

真正的 `config/config.yml` 在 `.gitignore` 里，但当前挂载目录里没有这个文件。因此没有可直接复制的真实 Pexels key。需要在 my-lovart 的 `.env.local` 里填：

```env
PEXELS_API_KEY=...
```

如果用户能提供 key，再跑一次真实搜索；在此之前只跑假 fetch 契约测试。

## 取舍

- 灵感图只是公开方向参考，不是客户产品实拍，不能作为 strict 正品锚图；
- 还需要“一次搜索锁”和结果缓存，避免反复搜图烧 Pexels 配额；
- 文字选图的编号以“最近一条含灵感卡片的消息”为准；同一项目里连续搜多次时，用点击加入对话更明确。
