# M35 · 答完问题后不能只给文字分镜就停

日期：2026-11-17
关联：`apps/server/src/features/agent/prompt.ts`、`docs/specs/golden-scenarios.md` G45

## 现场

用户做 10 秒公路车广告，答完 3 个提问卡（公路车 / 16:9 / 硬核速度感）。Agent：

- 调用了 `create_storyboard`，给出完整的 2 镜文字分镜；
- 结尾写“确认这版分镜后，我就先生成产品设定图给你看是不是这辆车。”；
- 然后本轮结束，没有调用 `generate_image`，也没有明确问用户“可以吗”。

Trace：`.traces/2026-11-17T04-15-34-921Z-…jsonl`，`run.event` 只有 `create_storyboard`，随后 `run.completed`。

## 根因

不是模型懒，而是两条规则叠加：

1. “建分镜先用 create_storyboard 写文字草稿……让用户确认；确认后再逐个生成” → 把“文字分镜”当成必须停下的确认点；
2. 没有“回合收尾”规则，模型可以用陈述句“确认后我就……”结束，既不做动作，也没给用户一个明确的回复入口。

## 修正

- 建完分镜后，除非用户明确说“先看文字/先别出图”，本轮继续做**可逆、低成本**的下一步：
  - 无参考图 → `generate_image(role=canon)` 产品/角色设定图；
  - 有参考图 → `register_reference`。
  把分镜和设定图一起给用户看；只有 `generate_video` 或批量关键帧才等待确认。
- 新增“回合收尾”：
  - 不要承诺“接下来我会做 X”然后停；
  - 需要确认时最后一句必须是明确疑问句或 `offer_choices`；
  - 工具失败说明缺什么并给替代方案，不连续重试配置错误。

## 验收

`run:video-confirmation-probe` 4/4（真实模型，两轮）：

1. 第一轮：3 个问题（offer_choices）；
2. 第二轮答完问题：`create_storyboard` + `generate_image` 同轮调用，不再只停在文字分镜；
3. 没有“确认后我就……”空承诺；
4. 结尾是明确问题（“你希望用哪种方式？”）或说明失败。

第一次跑时 VOLCES 回退 key 仍可出图，实际生成了一张 2048×1152 的设定图，也验证了成功路径；之后探针把 `VOLCES_API_KEY` 一并置空，避免再消耗额度。

## 仍然没做

- 生成 canon 后的“确认—关键帧”真实全链路没重跑（额度紧）；G38/G39 仍需重跑。
- `generate_image` 配置错误时模型仍可能重试一次（已加提示词禁止，未做服务端硬限次）。
