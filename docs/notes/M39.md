# M39 · 对话 Markdown 排版

日期：2026-11-17
关联：`apps/web/src/components/chat-markdown.tsx`、`chat-panel.tsx`、`chat-blocks.tsx`、`apps/web/src/app/globals.css`

## 现象

用户发来两张截图：

1. 三段方向说明（第 1 组/第 2 组/第 3 组）挤成一大段；
2. 4-6 列的脚本表格每列被压成一条竖线，字逐字换行。

不是模型没有输出换行，而是渲染层两个问题叠在一起。

## 根因

**单换行被 Markdown 折叠。** 模型习惯：

```
第1组 | 暖阳居家：……
第2组 | 暗调质感：……
```

这是同一段里的软换行（soft break）。CommonMark / `remark-gfm` 会把它渲染成空格，不会变成 `<br>`；只有空行才分段。`prose-muse p { margin: 0 }` 又去掉了段间距，所以视觉上完全糊在一起。

**表格没有样式。** GFM 表格解析是正常的，但 `globals.css` 只写了段落/列表/代码，没有 `table/th/td`。表格宽度被气泡压缩，列内容只能逐字换行。

## 修复

新增 `ChatMarkdown` 统一入口，聊天正文和交错文字块都用它：

- `formatChatMarkdown`：给非空行补两个行尾空格（Markdown 硬换行），代码围栏内原样保留；已有两个以上空格的行不重复加。
- `components.table`：包一层 `.md-table-wrap`，让表格在气泡内横向滚动，而不是压缩列宽。
- CSS：表格 `width: max-content; min-width: 100%`，单元格 6/8px 内边距、边框、`word-break`；表头不换行；最后一行/列去重边框；补 `blockquote` 样式。

没有引入新依赖：本环境 pnpm store 路径和宿主不一致，直接 `pnpm add remark-breaks` 会重链整个 `node_modules`；用行尾空格实现同样的硬换行语义，风险更小。

## 取舍

- 所有单换行都变成可见换行，模型故意用软换行连续成句的情况也会断行；聊天场景这是更常见的预期。
- 代码块内不处理，避免破坏 YAML/JSON/代码。
- 表格横向滚动而不是缩字号；列多时保持可读。

## 验收

- `apps/web` typecheck 通过。
- 用 `remark-parse + remark-gfm` 直接解析处理后文本：第一段出现 `break` 节点；6 列表格仍解析为 2 行 × 3 列（样例），没有被硬换行破坏表结构。
- 浏览器手测按 `docs/specs/manual-tests.md` T11：多行分点、6 列脚本表、代码块。
- 没有跑浏览器自动化；截图验收需要用户在本机确认。
