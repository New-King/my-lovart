# M37 · 聊天图片统一“加入对话”入口 + 搜图失败可见

日期：2026-11-17
关联：`apps/web/src/components/chat-blocks.tsx`、`chat-attachments.tsx`、`chat-panel.tsx`、`apps/server/src/features/agent/tools.ts`

## 1. 所有聊天图片都能一键加入对话

以前只有灵感卡片的缩略图有左上角箭头（`ArrowDownRight`），生成图、批量缩略图、用户消息里的图片都没有。现在统一：

- 单张生成图 `ImageCard`：hover/focus 显示左上角箭头，点击加入对话框并 toast；
- 多图横排 `CompactTile`：图片和视频海报都可加（视频不加，只加图片）；
- 用户消息附件 `MessageAttachments`：可以把自己发的图快速再次加入对话；
- 公共/上传素材、灵感卡片保持原行为。

注意结构：图片预览本身是 `<button>`，箭头必须作为兄弟节点覆盖，不能嵌套 button；外层用 `group relative`，箭头 `absolute left-1.5 top-1.5`。

## 2. 搜图未配置时不再“悄悄不搜”

用户说“没什么灵感”时，如果 `PEXELS_API_KEY` 为空，之前 `search_inspiration` 根本没注册，模型只能写“图片搜索暂时用不上”，过程里没有任何工具行，用户不知道是没调用还是失败。

改为：

- 工具始终注册；调用时返回 `invalid_config`，运行过程显示红色失败卡片；
- 提示词要求最多尝试一次，不重试，直接说明“灵感搜图暂不可用/缺少配置”，再用文字给 2–3 个方向；
- 搜索工具在全部方向都因鉴权失败时，错误码从 `inspiration_empty` 修正为 `invalid_config`，红色卡片能显示真实原因。

## 验收

- `verify:inspiration` 12/12：未配置 key 时工具仍注册，调用返回 `invalid_config`。
- `run:inspiration-unavailable-probe` 5/5（真实模型，key 为空）：
  1. 确实调用 `search_inspiration`；
  2. 过程里有 `invalid_config` 失败；
  3. 只调用 1 次，不重试；
  4. 回复说明搜图不可用，没有假装有结果；
  5. 仍给 3 个文字方向 + 提问卡。

## 已知边界

- 搜图失败卡片的红色展示依赖前端已有的 `tool.failed` 样式；本轮未改样式，只保证事件真的发出来。
- 图片“加入对话”用原始 URL；本地 `/files/:id` 会由服务端转 data URL 给模型，远端 Pexels URL 直接可用。
