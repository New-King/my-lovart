# M23 · 视频前期三层：canon / 关键帧 / 片段

## 现象

保温杯 10 秒广告：模型建了 4 个镜头，随后 4 次 `generate_image` 各自文生图。4 张图的杯子外形、材质、盖子都不同，像 4 个产品。用户质疑：这到底是分镜图、概念图还是设定图？5 秒为什么 4 张？怎么保证一致性？

## Trace 证据

`2026-11-15T07-44-41-955Z-882eca0c-a411-4be4-9242-d4b93fe8b4c1`：

- `create_storyboard`：4 个镜头，3+3+2+2=10 秒；
- 4 次 `generate_image` 的 input 只有 `title/prompt/aspectRatio/shotId`，**没有 inputImages/sourceAssetIds**；
- `projectAssetCount=0`，没有产品设定图，也没有用户产品实拍图；
- 每个镜头都从文字重新生成“奶白色竹木盖保温杯”，模型各画各的。

结论：不是 provider 不稳定，而是缺少共享参考和角色模型；而且 3 秒/2 秒的镜头低于视频单段最短 4 秒，不能逐段出片。

## Lavart 审计

Lavart 的 `video-generate.ts` 支持最多 7 张参考图，第一张作为首帧；前端面板支持首帧/尾帧上传；prompt 只有“视频 → generate_video”。没有 canon、storyboard、镜头时长或确认闸门。所以它没有解决这个问题，不能照抄。

## 实现

### 数据

migration `0010_video_preproduction.sql`（已在真实 Supabase 执行）：

- `storyboards.kind`（image/video）、`canon_asset_id`、`total_duration_seconds`
- `storyboard_shots.first_frame_asset_id`、`end_frame_asset_id`、`video_asset_id`
- 旧 `active_asset_id` 按资产 kind 回填到首帧/成片指针，保留兼容

### 角色

`ImageBlock.role`：`free | canon | keyframe | end_frame`；资产 `metadata.role` 同步。

- `generate_image({role:"canon", storyboardId})`：生成产品/角色设定图，自动挂到分镜；
- `generate_image({shotId, role:"keyframe"})`：`planImageReferences` 自动把 canon 放到参考图第一位；
- `generate_image({shotId, role:"end_frame"})`：可选尾帧；
- `generate_video({shotId})`：首帧/尾帧由服务端从镜头指针读取，不再接受模型临时换图；时长取 `shot.durationSeconds`。

### 时长规则

`create_storyboard({kind:"video"})` 校验：

- 总时长 4-15 秒；
- 每镜头 4-15 秒，合计等于总时长；
- 镜头数 ≤ `floor(总时长 / 4)`：5 秒 1 个，10 秒最多 2 个，15 秒最多 3 个。

5 秒拆 4 段会直接报错。

### 出片预检

`checkVideoPreflight` 顺序：

1. 无 shotId → `video_plan_required`
2. 镜头本轮新建 → `video_plan_unconfirmed`
3. 分镜没有 canon → `canon_required`
4. 没有首帧 → `keyframe_required`
5. 首帧 `metadata.role != keyframe` 或 `sourceAssetIds` 不含 canon → `keyframe_not_anchored`
6. 首帧本轮新出 → `keyframe_unconfirmed`
7. 通过；`direct=true` 仅在用户明确要求跳过时使用

### 上下文

`<project_state>` 现在带 `kind`、`duration`、`canon_id`；每个 shot 带 `first_frame_id`、`end_frame_id`、`video_id`。`get_storyboard` 返回这些指针和每个版本的 role。
