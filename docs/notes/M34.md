# M34 · 视频流程从固定流水线改成条件路径

日期：2026-11-17
关联：`docs/specs/video-preproduction.md`、`apps/server/src/features/agent/prompt.ts`、`apps/server/src/features/agent/tools.ts`

## 问题

用户上传一张角色图，说“生成 5 秒的视频，让这个人物站起来向我靠近”。Agent 回复“先做一版角色设定图给你确认人物形貌，再出镜头首尾帧和 5 秒成片”。

这不是一句提示词写错，而是整条视频链被设计成单一路径：

- 系统提示词把“需求 → 脚本 → 分镜 → 锚图组 → 首尾帧 → 确认 → 出片”写成所有视频的默认顺序；
- `checkVideoPreflight` 在非 loose 下强制 `canonAssetId`，否则 `canon_required`；
- `planImageReferences` 的 canon 只能由 `generate_image` 产出，用户提供的图没有入口变成 canon；
- 角色锚只写 `character_anchor_asset_id`，而 preflight 只看 `canon_asset_id`，角色视频即使有角色图也会被判缺 canon。

结果就是：用户已经给了主体图，系统仍然逼模型“生成角色设定图”。这是流程假设压过素材事实。

## 修正

1. **提示词改成 A–E 条件路径**：
   - A 单镜头/单动作 + 已有主体图 → `generate_video(inputImages, direct=true)` 直接 image-to-video，不生成设定图/首尾帧/分镜；
   - B 多镜头 + 参考图 → `register_reference` 把用户图登记为 canon，关键帧以它为参考；
   - C 多镜头 + 无图 → 才生成 canon；
   - D 纯文字单镜头 → 先首帧确认或用户明确要求时直接出；
   - E 要脚本/分镜 → 先文字。
2. **新工具 `register_reference`**：把 `<input_images>` 的 asset_id 或项目资产直接变成 canon（`origin=uploaded`），不重新生成。
3. **角色锚补 canon**：`setAnchorAsset(character)` 在没有 `canon_asset_id` 时同时写入 canon，避免角色视频被 `canon_required` 卡死。
4. **direct 服务端校验**：`checkDirectVideoInput` 只允许两种情况——有主体图的单条 image-to-video，或用户原话明确“直接出片/不用确认”。否则拒绝 `direct=true`。
5. 分镜规则改为“需要多镜头/连续性才建”；单条 image-to-video 不建分镜，也不对用户解释首帧/关键帧。

## 验收

- `verify:video-guard` 34/34：新增角色图直接登记 canon、角色锚写 canon、direct 有源图/无源图/用户显式授权三组。
- 真实模型行为探针 `run:image-to-video-probe` 5/5：输入一张角色图 + 原文“生成 5 秒的视频，让这个人物站起来向我靠近”，Agent 直接调用 `generate_video`，0 次 `generate_image`，0 次 `create_storyboard`，不说“先做角色设定图”。
- 探针故意清空 ARK/METASO key，确认工具失败时如实报告缺渠道，不偷偷改走设定图流程。

## 还没做

- 单条 image-to-video 目前不进分镜、不产 shot 记录；后续如果要把单条片段也纳入画布/资产版本线，可以补一个轻量 clip 记录，但不要重新引入固定前期。
- `direct` 的“用户原话授权”用正则判断，只覆盖显式说法；模型转述不算。宁可拒绝，也不要替用户跳过。
- 多镜头 B 路径还没有真实视频全链路手测；有额度时用角色图跑一次 10 秒 2 镜。
