# M17 · Phase 2a：异步作业与服务端画布写入

## 做了什么

- migration `0005_background_jobs.sql` 已执行：
  - `background_jobs` 表（image/video、queued/running/succeeded/failed/canceled、payload/result、attempt/maxAttempts）
  - `claim_background_job()` 用 `for update skip locked` 原子领取，多个 worker 不会重复执行
- `features/jobs/jobs.ts`：创建/查询/取消/领取/成功/失败/等待作业
- `features/jobs/worker.ts`：API 进程内 worker，默认并发 2，1s 轮询；图片/视频 executor；失败按 attempt 重试；超时标记 job_timeout
- 图片/视频工具改为提交作业并等待：
  - 图片最多等 120s，视频最多等 600s
  - 超时返回 `jobId/jobType`，前端继续轮询
  - 作业基建不可用时自动退回原来的直连生成
- `features/canvas/server-canvas.ts`：
  - 作业完成后服务端计算落位（400×500、原点 56、同行间距 24）
  - 写 `canvases.elements` + `files`，并用 project 级写锁串行化
  - 元素写 `customData.assetId/title/prompt`，和前端自动插入互斥
- 前端：
  - artifact 带 `elementId` 时不再重复插画布，改为 `syncFromServer()` 拉取
  - 工具超时 `tool.failed.error.jobId` 触发 fallback 轮询（5s，最多 10 分钟），成功后刷新画布
  - 新增作业查询/取消 API 与客户端方法
- 删除项目时清理 Storage：
  - 项目画布文件目录
  - `project_assets` 与消息附件对应的 `attachments/*`
  - checkpoint thread（Phase 1d 已有）

## 验证

真实 Seedream（29.4s）：

- 用户：“直接生成一张 3:4 的暖秋咖啡海报”
- Agent 调 `generate_image` → `background_jobs` 状态 `succeeded`，attempt=1
- `project_assets` 有「暖秋咖啡海报」
- `canvases.elements` 有对应 image 元素，`customData.assetId` 与资产 id 一致
- SSE 返回 artifact 且带 `elementId`，前端路径不会重复插入
- worker 日志：开始 → 完成 +29411ms

Storage 清理：

- 造了项目画布文件 + `attachments/*` + asset 行，调用 `POST /projects/:id/delete`
- 删除后 Storage 两个路径都为 0，项目行也为 0

取消路径：

- 工具等待中 abort 会 `cancelJob`，worker 生成完成后检查 canceled，不再写画布/资产
- 该路径还没做真实“生成中取消”手测（需要一次长任务）

## 还没做

- 视频作业只做了执行与对话产物，**视频画布元素/内联播放**仍未做
- 作业进度没有持续推给工具卡片（只有“提交生成作业”一步）
- 非重试错误也会重试到 maxAttempts，后续按 error code 区分
- 多实例 worker 的公平性和限流还没做
- 作业超时后的 fallback 轮询只做了代码路径，未构造真实超时手测
