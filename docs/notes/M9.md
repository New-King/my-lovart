# M9 · 提示词重构与上下文

## 问题

前几轮为了修具体的回复问题，system prompt 被不断追加规则，最后变成一份堆满「不要…」的清单：

- 把 `<canvas_state>` 写成「唯一事实来源」，还要求「画布为空时明确说画布是空的」；
- 空画布也每轮注入 `<canvas_state>画布目前为空…</canvas_state>`；
- 结果模型每次说话都先汇报画布状态，甚至在用户只是打招呼、问需求时也说「画布上没有东西」。

## 对照 Lavart

Lavart 的提示词按「画布感知 / 任务完成 / 工具选择 / 参考图片 / 画布操作」分段，画布只是背景信息：「你已经知道画布上有什么，直接基于这些信息行动即可」，没有要求汇报空画布。它的空画布直接返回 `null`，不注入 `<canvas_state>`。对话记忆靠 LangGraph checkpointer（thread_id），不是每轮重放文本历史。

## 改了什么

- 提示词移到 `apps/server/src/features/agent/prompt.ts`，按「对话与上下文 / 需求确认 / 工作方式 / 表达」重写，减少否定式堆叠
- 画布状态改为背景信息：只有用户问起或任务依赖画布时才提；空画布不再注入 `<canvas_state>`
- 需要知道画布是否为空时，由模型主动调用 `inspect_canvas`，工具此时返回「画布目前为空」
- 历史消息排除当前这条用户消息，避免同一条消息以纯文本和带 XML 两种形式各传一遍
- 前几轮用户发过的参考图继续注入 `<input_images>`，和画布内容明确区分

## 验证

- 空画布说「你好」→ 正常打招呼，不提画布
- 空画布说「我想做一个视频」→ Markdown 三问，不提画布为空、不出按钮
- 空画布说「把这 3 张图做成视频」→ 明确说画布是空的、没拿到图片，让用户上传（用户主动提到图片时才说明）
- 有历史附件说「加点过年元素」→ 直接调用 `generate_image` 做图生图，不要求重传

## 已知问题

- 还没有接 checkpointer；历史仍是消息文本重放，工具调用细节不会跨轮保留
- 附件 asset_id 是每轮按顺序生成的（asset-1…），接 checkpointer 前需要先改成稳定 id，否则旧消息里的 asset_id 会和新轮次冲突
