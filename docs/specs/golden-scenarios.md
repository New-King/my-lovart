# Golden 场景

每个场景都必须可复现。通过标准是“表现符合 expected，且不出现 forbidden”。  
实现改动前先引用场景编号；改动后在真实模型上至少跑受影响场景。

## G01 空画布打招呼

- 上下文：空画布，无附件，无历史
- 输入：`你好`
- 期望：正常打招呼，说明能做什么；不调用工具
- 禁止：提“画布目前为空”；主动列需求表单；出按钮

## G02 空画布做视频

- 上下文：空画布
- 输入：`我想做一个视频`
- 期望：Markdown 列 2-3 个关键问题（内容、平台/画幅、时长/基调）；不调用生成工具
- 禁止：说“画布上有 3 张图”；直接调用 `generate_video`；出按钮

## G03 视频信息只回答一半

- 上下文：上一轮已问平台、内容、风格、时长
- 输入：`就是 5 秒的宣传视频，品牌叫 newking`
- 期望：确认已收到的信息，继续问平台/画幅与内容/调性；不生成
- 禁止：自行默认 3:4 或暗调后调用 `generate_video`；重复问时长和品牌

## G04 只差一个离散项

- 上下文：空画布
- 输入：`做一张咖啡海报，3:4 竖版，暖色调，只差投放场景没确定`
- 期望：一句承接 + 一个问题；调用 `offer_choices` 给 1-3 个投放场景答案；不生成
- 禁止：给“下一步动作”按钮；正文长篇分析；直接生成

## G05 图片附件识别

- 上下文：当前消息带一张人物图，文件名 `祽祈.jpg`
- 输入：`这是谁`
- 期望：基于画面描述角色/作品，或说明不确定；可以提到文件名但不只靠文件名
- 禁止：说“只拿到文件信息，看不到画面”

## G06 跨轮沿用参考图

- 上下文：上一轮用户发过参考图，本轮无附件
- 输入：`加点过年元素`
- 期望：直接拿 `<input_images>` 的 asset_id 做图生图；调用 `generate_image`
- 禁止：让用户重新上传；说画布为空所以没有图

## G07 空画布声称有图

- 上下文：空画布
- 输入：`把这 3 张图做成一个视频`
- 期望：明确说画布是空的、没拿到图片，请用户上传；不调用视频工具
- 禁止：编造图片内容；假装已经生成

## G08 画布并排

- 上下文：画布三张不同高度的图
- 输入：`把这三张图排成一行，顶部对齐`
- 期望：调用 `manipulate_canvas`，下发 align(top) + distribute 或 move；一句话说明
- 禁止：重新生成图片；编造 element id

## G09 画布删除

- 上下文：画布至少两张图
- 输入：`删掉第二张`
- 期望：识别正确元素，调用 `manipulate_canvas` delete；说明已删除
- 禁止：删除错误元素；说“画布没有东西”

## G10 多版本生成与交错

- 上下文：空画布
- 输入：`先做一张暖秋咖啡海报，做完告诉我，再做一张极简版`
- 期望：文字 → 第一张图 → 文字 → 第二张图 的顺序；两张 artifact
- 禁止：所有文字堆在图片上方；只生成一张却声称两张

## G11 工具失败

- 上下文：provider 返回错误
- 输入：任意生成请求
- 期望：工具卡片 failed，回复说明真实错误和替代方案
- 禁止：假装成功；空回复；无限重试

## G12 用户取消

- 上下文：视频生成中
- 输入：点击停止
- 期望：run.canceled；保留已产出部分；状态显示已停止
- 禁止：消息永远停在生成中；后台继续写入

## G13 刷新恢复

- 上下文：完成一轮带图片的对话
- 输入：刷新页面 / 重启服务
- 期望：消息、文字/图片顺序、画布元素、图片文件全部还在
- 禁止：图片 404；历史清空；状态回到 queued

## G14 编辑画布不误生成

- 上下文：画布有图
- 输入：`把第一张放大到 80%`
- 期望：只调用 `manipulate_canvas` resize；不调用 `generate_image`
- 禁止：重新生成；改错元素

## G15 纯文字任务

- 上下文：任何
- 输入：`帮我写一句海报文案`
- 期望：直接文字回复，不调用视觉工具
- 禁止：调用 `generate_image`；出画布状态汇报

## G16 跨轮引用已生成图片

- 上下文：上一轮生成过「暖秋咖啡海报」，资产已入账，但用户把画布上的图删了
- 输入：`把刚才那张咖啡海报改成夜间版`
- 期望：从 `<project_assets>` / `get_asset` 找到标题、prompt、asset_id，直接图生图
- 禁止：说“找不到那张图”；让用户重新描述；重新问尺寸和风格

## G17 修改第 3 个镜头

- 上下文：6 镜头分镜，第 3 镜头已有 active 资产
- 输入：`第 3 个镜头改成俯拍，其他不动`
- 期望：`get_storyboard` 定位 shot_id → `update_shot` → 只重做该镜头 → 新版本成为 active
- 禁止：重做整个分镜；改错镜头；覆盖旧资产

## G18 重置分镜

- 上下文：6 镜头分镜，均有资产
- 输入：`把分镜重置一下，我想重新来`
- 期望：先说明影响（6 个镜头当前版本清空、历史资产保留）并确认；确认后写 revision、清 active
- 禁止：静默删除资产；重置后无法恢复；直接开始批量生成

## G19 版本回退

- 上下文：第 2 镜头有 v1/v2/v3 三版
- 输入：`第 2 个镜头用回第二版`
- 期望：`list_assets({shot_id})` 找到 v2，`set_shot_asset` 切回；不重新生成
- 禁止：重新生成一版冒充回退；删除 v3

## G20 两个分镜并存

- 上下文：项目里有「品牌宣传片」和「产品开箱」两个分镜
- 输入：`给产品开箱那个的第 2 镜头加一个转场`
- 期望：按标题找到正确 storyboard_id，只改目标镜头
- 禁止：改到另一个分镜；凭记忆编 id

## G21 资产很多时的上下文预算

- 上下文：项目有 40 个资产、3 个分镜
- 输入：`看看之前生成的封面有哪些`
- 期望：`list_assets` 分页/筛选返回摘要；上下文不塞全部 prompt
- 禁止：把所有资产完整 prompt 注入；编造不存在的资产

## G22 无分镜无资产

- 上下文：新项目，空画布，无产物
- 输入：`继续`
- 期望：不注入空 `<project_state>` / `<project_assets>`；不主动汇报“项目里什么都没有”
- 禁止：每轮都说“目前没有资产/画布为空”

## G23 生成失败保留状态

- 上下文：分镜第 4 镜头已有 v1，重做时 provider 失败
- 输入：`重做第 4 个镜头`
- 期望：镜头仍指向 v1，状态回到 failed/draft，说明真实错误；可重试
- 禁止：清空 v1；把镜头标成 ready；假装成功
